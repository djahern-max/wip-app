# F09.3 · Imports page

**Roadmap phase**: B (an addition after F09.2; nothing moved) · **Blueprint refs**: §12 (frontend) · **Decisions**: D-22, D-47 referenced; none made here

## Why
The third design feature. The owner, 2026-10-08, after F09.2 was live: the upload page needs the same treatment. Built directly on the pieces F09.2 made (no mockup first); the owner judges the rendered page.

## Scope
Layout, style and one new sentence. **No API response, no permission and no upload behaviour changes.** Frontend only; nothing in `backend/`.

1. **Upload form** (`Imports.jsx`): Source, File and "Upload file" on one line on a laptop, stacked on a phone, in one card. The file control is styled like the other controls. While a source or a file is missing the form says "Choose a source and a file, then upload." (new sentence); the upload notice and the error take its place when there is one. Source is still remembered per company for the session, still opens on "Choose a source", and "Upload file" still waits for both.
2. **Uploaded files**: a heading with "Refresh" as a button at its right (it was a link above the table). Six columns instead of nine: the file with its source and size under it; Status with its message and row sentences; Rows loaded; Rows skipped; Uploaded with the person under it; Download. Nothing shown before is dropped.
3. With no files, a plain card with the existing sentence instead of a one-row table.
4. Below 640 px the files are still cards (unchanged), now on a white ground.

**Shared styles** (`styles.css`): `.upload-form`, `.upload-note`, `.file-input`, `.section-head-wide`. No new colour; the accent's users are unchanged.

## Acceptance criteria
- [x] The page renders at 1280 px and 390 px, with files and without, with no sideways page scroll (rendered in Chromium with stand-in data: document width equals the viewport; no page error).
- [x] One primary action on the screen, "Upload file" (`test_one_primary_action_per_screen`).
- [x] The checks on this page in `test_frontend_styles.py` still pass unchanged: machine tokens are not rendered; the chosen source is kept; "Choose a source"; `disabled={busy || !file || !kind}`.
- [x] `npm test` 84 pass; `vite build` succeeds.
- [ ] The owner's pass on jobcost.dev, tenant `rye-beach`: upload a real estimate template (the notice, then Refresh, then its row); upload the same file again (the "already uploaded" sentence); a file that fails (its sentence in red); Download; at 390 px.

## Not verified
- No real upload was made: the form was rendered and its controls looked at, not submitted.
- The backend test suite was not run (no database in the build environment); this feature changes no backend file.

## Discovered (not fixed here)
- "Refresh" re-reads the list by hand; the page does not say when it was last read, and a file being processed looks the same until Refresh is pressed.
- Dates in the files list use the browser's own format ("9/22/2026, 10:14:05 AM"), unlike the accounting dates elsewhere (2026-09-22).
