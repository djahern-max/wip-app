# F09.1 · Interface foundation, header and Home

**Roadmap phase**: B (an addition after F09; nothing moved) · **Blueprint refs**: §12 (frontend) · **Decisions**: D-22 referenced; **D-47 made here** (2026-10-08)

## Why
The owner's pass on Home at phone width, 2026-10-08: not usable. The header wrapped at random and cut off "Configuration"; the set-up checklist was a four-column table whose Action column was off the screen; "firm_admin" was shown three times. The owner approved a mockup of the header and Home (laptop and 390 px) before any code changed.

## Scope
Layout, style and display words only. **No figure, no API response and no permission changes.** Frontend and one static test; nothing in `backend/app/`.

1. **Shared styles** (`frontend/src/styles.css`): the page sits on a light grey ground with white header, cards and tables; a type scale for h1 to h3; buttons 44 px high with a visible border; a focus ring.
2. **Header** (`Shell.jsx`): brand, company and account on one line, the navigation on its own row, wrapping; the current page is marked. Below 640 px the navigation and account fold behind a "Menu" button. The company picker shows the company's name (and, for firm users, the open-exception words as before), no role.
3. **Home** (`Home.jsx`, `home.js`): the set-up checklist is a numbered list with a progress line ("1 of 5 steps done"); each step shows its name, the API's sentence, "Done" or "Not done" and its one action. The API's primary line is still the one primary action. "Your role here" is gone; the role is in the header.
4. **Roles in words** (`roles.js`): Firm admin, Firm staff, Client admin, Project manager, Viewer.
5. The "API ok · database ok" line moves from the bottom of every page to the footer.

## Acceptance criteria
- [x] Every nav item is reachable at 1280 px and at 390 px; nothing is cut off; the page never scrolls sideways (rendered in Chromium at both widths with stand-in data: document width equals the viewport).
- [x] Home's checklist shows step, sentence, status word and action without sideways scrolling at 390 px.
- [x] At most one primary action on the screen (`test_one_primary_action_per_screen` unchanged and passing).
- [x] No role code on screen (`test_roles_reach_the_screen_as_words`; `roles.test.js`).
- [x] The accent is used only where D-47 allows (`test_one_accent_colour_used_only_where_d47_allows`); no shadow, gradient, animation or transition (`test_system_font_stack_and_no_decoration` unchanged).
- [x] `npm test` passes (82); `vite build` succeeds.
- [ ] The owner's pass on jobcost.dev, tenant `rye-beach`, at laptop width and 390 px: header, Menu, Home; and a look at Jobs, a job page, Exceptions, Imports and Configuration for anything the shared styles made worse.

## Not verified
- The backend test suite was not run (no database in the build environment); the functions in `tests/test_frontend_styles.py` were run directly and pass. Run `make test` before deploying.
- Only Home was rendered. The other screens take the new ground colour, heading sizes and button style and were not looked at.

## Discovered (not fixed here)
- `backend/app/domain/home/checklist.py`, `suggestion_rules`: the sentence shown to a person names a runbook ("OPERATIONS, Editing suggestion rules") and says "there is no screen for this". Wording for the owner to decide; it is backend copy with its own tests.
- A step that waits on another ("Account mapping waits for the chart of accounts") reads "Not done" like any other. The mockup showed "Waiting on step 3"; that needs a field from the API and a second status colour (D-47 point 2).
- The working screens (Jobs, the job page, Exceptions, Estimates, Customers, Imports, Configuration, Connections) are not redesigned; each is a later design feature.
- `.header-brand` is declared twice in `styles.css` (the logo block and the frame block); harmless, tidy with the next style change.
