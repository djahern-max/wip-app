Owner's answers baked in: the wordmark reads `jobcost.dev` (the hostname, D-27), `PRODUCT_NAME` stays `jobcost`; the logo is the hammer at `frontend/public/brand/logo.svg`, already committed.

### Goal
One image is the brand. `frontend/public/brand/logo.svg` is the only hand-made picture in the repo; every other brand asset the browser, the phone home screen or a link preview asks for (favicons, touch icon, PWA icons, manifest, Open Graph image) is generated from it by one script and committed. The app shell, the sign-in page and the three static pages show the logo from that one file. Replacing the logo later is: overwrite `logo.svg` (and `logo-mark.svg` to match, or the 16 and 32 px favicons fall back to the line art), run `npm run brand`, commit, deploy. Renaming the product later is still D-09: one constant per side, and the assets follow from it on the next `npm run brand`. Nothing here touches the backend, the database, the CSP, or the product name.

### In scope
**Source (`frontend/public/brand/`)**
- `logo.svg`: the owner's hammer, committed as supplied. The script reads it; nothing edits it. Vite copies `public/` to `dist/` unchanged, so it is served at `/brand/logo.svg` under `img-src 'self'`. It carries no colour (no `fill` on any path), so it renders black everywhere.
- `logo-mark.svg` (plan question 4): `logo.svg`'s outer outline filled, derived 2026-09-26 by dropping the inner subpath of each of the three paths; the line art does not read at 16 px (0.43 px strokes). Used for the 16 and 32 px favicons only. A replacement `logo.svg` needs a matching `logo-mark.svg`, or those two favicons fall back to the line art (the script says which it used).
- `brand.json` (new, hand-edited, three keys): `"background"` (the solid colour behind the touch icon and the OG image), `"foreground"` (the wordmark colour), `"padding"` (fraction of the icon box left clear around the logo on the touch and PWA icons, 0.15 to start). Not the wordmark text: that is built from the constants in `src/product.js`. Starting values (plan question 3): `background` `#fff` = `--surface`, `foreground` `#000` (the hammer's own black, so the wordmark matches it exactly; `--text` is `#1a1a1a`), `padding` 0.15. The colours are hand-copied from `styles.css` and do not follow it; `--accent` appears nowhere in the brand assets.

**Constants (`frontend/src/product.js`)**
- Add `export const SITE_HOST = "jobcost.dev";` next to `PRODUCT_NAME` and `SUPPORT_EMAIL`. The wordmark and every `og:` value use `SITE_HOST`; `PRODUCT_NAME` is unchanged. (`tests/test_product_name.py` excludes the hostname form on purpose, so this passes as written.)

**Generator (`frontend/scripts/make-brand.mjs`, `npm run brand`)**
- Reads `public/brand/logo.svg`, `public/brand/brand.json` and `src/product.js`; writes into `public/`:
  - `favicon.svg` (the logo as is), `favicon-16.png` and `favicon-32.png` (from `logo-mark.svg` when present, else the logo), `favicon-48.png` (the logo), and `favicon.ico` holding those three PNGs (an ICO container of PNG entries, written by the script; no extra dependency).
  - `apple-touch-icon.png` (180 × 180, `background` fill, logo inset by `padding`), `icon-192.png`, `icon-512.png` (same treatment), and `icon-512-maskable.png` (padding doubled).
  - `site.webmanifest`: `name` and `short_name` = `SITE_HOST`, `start_url` `/`, `display` `standalone`, `background_color` and `theme_color` = `background`, the two PWA icons plus the maskable one.
  - `og-image.png` (1200 × 630): `background` fill, the logo on the left at 60% of the height, the wordmark `SITE_HOST` to its right in `foreground`, set in `"Helvetica Neue", Helvetica, Arial, sans-serif` (real family names: sharp renders text through fontconfig, which does not know the browser generics `system-ui` and `-apple-system`). Composed from an SVG the script builds and rasterises; no third-party image in it.
  - `brand-manifest.json`: the SHA-256 of `logo.svg`, of `logo-mark.svg` (null when absent), of `brand.json` and of `product.js` at generation time, and the list of files written. CI reads it (below); so does `tests/brand.test.js`, so a stale manifest fails `npm test` before it reaches CI.
- Rasterisation by `sharp` (devDependency; see Dependencies). The script is deterministic for a given logo, `brand.json`, `product.js` and machine; outputs are committed, so CI and `deploy.sh` never run it.

**Markup**
- `frontend/index.html`: `<title>` becomes `SITE_HOST`'s value written literally (`jobcost.dev`; the hostname form is allowed by the product-name test, the bare name is not). Add `<link rel="icon" href="/favicon.ico" sizes="48x48">`, `<link rel="icon" type="image/svg+xml" href="/favicon.svg">`, `<link rel="apple-touch-icon" href="/apple-touch-icon.png">`, `<link rel="manifest" href="/site.webmanifest">`, `<meta name="theme-color">` = `background`, and the preview set: `og:type` website, `og:site_name` and `og:title` = `jobcost.dev`, `og:description` one sentence ("Job cost and WIP reporting for contractors, operated by a CPA practice."), `og:url` `https://jobcost.dev/`, `og:image` `https://jobcost.dev/og-image.png` with `og:image:width` 1200 and `og:image:height` 630, `twitter:card` `summary_large_image`. Plain markup only: no inline `<script>` or `<style>`, so the F05.0 CI check and the CSP stand.
- `frontend/public/privacy.html`, `terms.html`, `qbo-disconnected.html`: the same icon `<link>`s (no `og:` set; they are not shared), and one `<img src="/brand/logo.svg" alt="" width="28" height="28">` at the top of `<main>` before the `<h1>`, styled by one rule added to `pages.css`. The entity line, the address, `Last updated` and the once-per-page domain mention are unchanged (`tests/test_deploy.py` counts them).
- `frontend/src/Logo.jsx` (new): `<img src="/brand/logo.svg" alt="" className="logo" width={size} height={size}>`; the `alt` is empty because the text beside it names the product. Used in `pages/Shell.jsx` (header, 24 px, before the `<strong>{PRODUCT_NAME}</strong>`) and `pages/Login.jsx` (above the `<h1>{PRODUCT_NAME}</h1>`, 48 px). The SVG is never inlined into JSX.
- `frontend/src/styles.css`: `.logo { display: inline-block; vertical-align: middle; }` and `.header-brand` (an inline-flex pair, logo and product name, with a 0.5rem gap); nothing else.

**Deploy and CI**
- `deploy/nginx/jobcost.dev.conf`: no change. `/favicon.ico`, `/og-image.png`, `/site.webmanifest`, `/brand/logo.svg` are files under `root`, served by the existing `try_files $uri /index.html`; they carry the security headers from the server-level include. (`og-image.png` is fetched by link previewers with no cookies; `img-src` does not apply to them.)
- `.github/workflows/ci.yml`, frontend job: after `npm run build`, the existing Python step also asserts that `dist/favicon.ico`, `dist/favicon.svg`, `dist/apple-touch-icon.png`, `dist/icon-192.png`, `dist/icon-512.png`, `dist/site.webmanifest`, `dist/og-image.png` and `dist/brand/logo.svg` exist, and that the SHA-256 of `dist/brand/logo.svg` (and of `dist/brand/logo-mark.svg`) equals the one recorded in `dist/brand-manifest.json`. A swapped logo committed without `npm run brand` fails CI with that sentence.
- `docs/OPERATIONS.md`: a "Brand" section: where the logo lives, what `npm run brand` writes, the swap procedure (overwrite, run, commit, deploy), and that the product name is D-09 and not changed here.

### Out of scope
Renaming the product (D-09; `PRODUCT_NAME` is untouched). A marketing site or landing page (there is none; `/` is the sign-in page). E-mail templates (none exist yet). Dark-mode variants of the logo. Any change to the CSP string, the nginx site file, `deploy.sh`, `setup.sh`, or the backend. A component library or design tokens beyond the three keys in `brand.json`. Editing `logo.svg` in any way (cleaning, recolouring, adding a wordmark to it): the owner supplies the file as is. A PNG copy of the logo in `brand/` (the raster forms are generated). Search-engine metadata beyond the preview set (`robots`, sitemap, structured data).
