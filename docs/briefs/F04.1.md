## F04.1 · Policy screen a person can answer
**Roadmap phase**: A · **Blueprint refs**: §5 (`tenant_policy`), §8.3 · **Decisions**: D-22, D-02, D-04, D-05 referenced (none made here; D-08 stays open)
**Status**: drafted 2026-10-05 by the owner's design partner; built 2026-10-05 (go-ahead the same day; commit ba0eda0); closed 2026-10-05 on the owner's pass on jobcost.dev, tenant `rye-beach`. A patch under F04; it changes no accounting behaviour, adds no table and no policy key. It amends one F04 acceptance criterion on the owner's instruction (2026-10-05): the decision reference becomes optional.

### Goal
The owner opened Configuration, Policy on `rye-beach` (2026-10-05) and could not answer it: the time zone wants a name nobody knows by heart, every key demands a typed decision reference, and two keys ("Deposit identification", "Fuel surcharge treatment") are free-text boxes with no hint of what to type. After this patch the screen asks only what a person can answer today, in words they know, and says plainly which keys wait and for what. Who decided and when are still recorded on every change. No key gains a default and no stored value changes.

### In scope
**Time zone**
- The edit control is a drop-down, not a text box. Options are the United States zones in plain words, each carrying its zone name as the stored value: Eastern (`America/New_York`), Central (`America/Chicago`), Mountain (`America/Denver`), Arizona (`America/Phoenix`), Pacific (`America/Los_Angeles`), Alaska (`America/Anchorage`), Hawaii (`Pacific/Honolulu`).
- A decided value shows as its plain-words label with the zone name beside it, e.g. "Eastern (America/New_York)". A stored value that is not on the list (set earlier through the API) is shown as its zone name and is offered in the drop-down so saving does not lose it.
- Server validation is unchanged: any valid zone name is still accepted by `PUT /api/config/policy/timezone`.

**Decision reference is optional**
- `set_policy` and the route accept a blank or missing `decision_ref` for every key. The "Record decision" button no longer waits for it. The label becomes "Reference (optional): where this is written down, e.g. D-04 or the engagement letter".
- `decided_by` and `decided_at` are recorded exactly as today. The audit row is written exactly as today, with the reference blank when none was given.
- The Reference column shows nothing for a blank reference (no "None", no dash).

**Keys that wait for their feature**
- The registry (`POLICY_KEYS`) gains one field saying which keys cannot yet be set on the screen and why. Three keys carry it:
  - `small_job_threshold`: "Not decided (D-08). Set when the WIP schedule arrives."
  - `deposit_identification`: "Set with the billing reports (F08)."
  - `fuel_surcharge_treatment`: "Set with the billing reports (F08)."
- For these keys the Policy table shows that sentence in place of the "Decide" link, and `PUT /api/config/policy/<key>` is refused with one plain sentence saying the same. A value already stored on any tenant is still shown, with who and when, and is not removed.
- The feature that first reads a key removes the marker and gives the key its proper control in the same change, as it adds the key to `REQUIRED_POLICY_KEYS` (F07.3).
- Descriptions rewritten: `deposit_identification` → "The QuickBooks item a deposit invoice uses (D-02)."; `fuel_surcharge_treatment` → "How a fuel surcharge line on an invoice is recognised." (the "(D-04)" citation is removed: D-04 is about fuel as a cost, not a surcharge billed to a customer); `small_job_threshold` keeps its sentence.
- `timezone`, `fiscal_year_start_month` and `wip_basis` stay settable as today.

**Small fixes on the same table**
- "Not decided" is left-aligned for every key. Today the money key right-aligns it (`.num` is applied whether or not the key is decided); `.num` applies to a decided money value only.
- The WIP basis edit shows one line above the tick boxes: "Tick the same cost categories that are counted in cost to date and in EAC (BLUEPRINT §8.3)." No box is pre-ticked.

**Docs**
- `docs/briefs/F04.md`: one dated note under the `tenant_policy` acceptance criterion: "Amended by F04.1 (owner, 2026-10-05): the decision reference is optional; who and when are unchanged." Nothing else in that file is edited.
- OPERATIONS.md "New client set-up", Policy step: choose the time zone from the list; tick the WIP basis; the reference is optional; three keys wait for their features.
- ROADMAP: add an `F04.1` line directly under F04 with its status. Nothing else moves.
- BLUEPRINT: no change. CLAUDE.md Vocabulary: no change.

**Dependencies**: none. Anything new: stop and ask.

### Build notes (2026-10-05)
The owner's answers to the five Plan questions, and what was built on them:
1. `tenant_policy.decision_ref` is `NOT NULL` (model and migration 0005). A blank or missing reference is stored as the empty string; the API reads it as none; the audit row carries `"decision_ref": ""`. No migration.

5. The dev `wip` database (at 0012) holds no `tenant_policy` row on any tenant. Home's "4 more keys" counts `fiscal_year_start_month` plus the three waiting keys and does not read the marker; unchanged.
