## 2026-09-17 · F02.1 · enrolment idempotency fix
**What**: `POST /api/auth/totp/enrol` is idempotent while an enrolment is pending: it locks the user row (`SELECT … FOR UPDATE`, re-read under the lock) and returns the stored unconfirmed secret, generating one only when none is pending; already enrolled is still 409. A pending secret (secret present, `totp_enrolled_at` NULL; no schema change) is dropped by `_clear_pending_totp()` when a new activation link is issued, when a link is redeemed, and at a successful password login (a client user starts optional enrolment from a normal session, so the next login is the "later enrolment session"); admin TOTP reset already cleared it; confirm turns it into the enrolled secret. `TotpEnrol.jsx` keeps its one enrol request in a ref, so StrictMode's doubled mount effect sends one request; StrictMode stays on.
**Why**: Owner browser pass. React 18 StrictMode ran the mount effect twice in dev, two concurrent enrol calls each wrote a new secret, the server kept the last write and the screen showed either one, so codes never matched. A refresh, a double click or a retry did the same in production. The F02 end-to-end check was the API flow through the Vite proxy with one call per step, and every backend test called enrol exactly once, so no check ever made the second call.
**Tests**: 222 pass (217 + 5): two sequential enrol calls return the same secret and URI, the secret is stored as key-ring ciphertext, a code from the first response confirms, and the same ciphertext becomes the enrolled secret; two concurrent calls return the same secret (the test holds the user row lock until both requests queue on it; with `FOR UPDATE` removed the test fails with two different secrets, checked by hand and reverted); issue-link and admin TOTP reset clear a pending secret at once and the next enrolment gets a different one; redemption clears on its own; a client user's abandoned secret is gone at the next login. Response scan and log capture pass unchanged. `npm run build` passes. The owner browser-pass criterion stays unticked.
