## 2026-09-17 · F02 · Auth, roles, audit log
**What**: Hand-rolled authentication (D-10): e-mail + argon2id password (12+ chars), 5-failures-in-15-minutes lockout with identical "unknown e-mail" / "wrong password" responses, TOTP (RFC 6238, ±1 step, stored time-step counter so a code cannot be replayed) mandatory for `firm_admin` / `firm_staff` and optional for client roles, ten hashed one-time recovery codes, `firm_admin` password-reset links (returned to the admin, no e-mail) and TOTP resets, and `scripts/create_user.py` for bootstrap and last-resort resets. Server-side sessions in the new global `session` table (256-bit id in an `HttpOnly; Secure; SameSite=Lax` cookie, only the SHA-256 stored; id rotates at login and at TOTP verification; idle 60 min and absolute 12 h from environment; logout deletes the row). CSRF middleware requires `X-Requested-With` on every `POST/PUT/PATCH/DELETE` under `/api/`. Tenant context now comes only from the session: `require_tenant_id` reads the principal, the `X-Tenant-Id` header is gone; `get_principal` sets `app.user_id` and `app.tenant_id` with `set_config(..., true)` on the one request transaction. D-11 own-membership `FOR SELECT` policy via `allow_own_membership_read()`, and `tests/test_rls.py` now allow-lists extra policies (exactly one). Tenant switcher (`GET /api/session/tenants`, `POST /api/session/tenant`), auto-selection for single-membership users. `app/core/authz.py`: `require_roles` / `require_firm_role` and named capabilities (`can_view_pay_rates` = firm_admin, firm_staff, client_admin, …); a test-only probe router mounts one route per capability under pytest. `firm_admin` endpoints for users, memberships (in any tenant of the firm, including one with no members yet), resets. Audit (D-12, D-13): tenant-scoped `audit_log` (RLS) and global `firm_audit_log`, both insert-only via `make_append_only()` triggers and registered in `APPEND_ONLY_TABLES`; plain JSON read routes `GET /api/audit` (firm roles + client_admin) and `GET /api/firm-audit` (firm roles). `app/core/crypto.py`: AES-256-GCM key ring with key id stored beside the ciphertext, used for TOTP secrets. Frontend: login, TOTP verify (with recovery-code option), TOTP enrolment (QR + manual key, recovery codes shown once), reset-password page, shell with tenant switcher and sign-out; unauthenticated users see only the login page. Housekeeping from the F01 review: compose host port from `POSTGRES_HOST_PORT` (default 5433); this CHANGELOG template gained **Tests** and **Dependencies added**. Also fixed: `Settings` now reads the repo-root `.env` when run from `backend/` (F01's defaults had hidden that it was never loaded).
**Why**: BLUEPRINT §3.8 and §11: every request is tied to an authenticated user, a role, and a tenant taken from the server-side session, never from the client. Firm-level authority is **derived from memberships** (no schema change; see the F02 plan for the `firm_membership` proposal, D-15 candidate). Expected failures that must be persisted (failed login, failed code, lockout) are returned as results and rendered as 401/429 so the request transaction commits; failures that must roll back (403 on tenant switch) raise. `session` stores the active tenant as `active_tenant_id` so the RLS enumeration does not mistake the global table for a tenant table. `firm_audit_log.firm_id` is nullable because an unknown-e-mail failure has no firm.
**Migrations**: `0002_auth_audit` (reversible; verified up → down → up on a scratch database in a test and on `wip` via the CLI). Adds credential columns to `user`; creates `session`, `audit_log` (RLS + append-only), `firm_audit_log` (append-only); creates the `own_membership_read` policy and the `raise_append_only()` trigger function.
**Tests**: 150 passing (F01: 25). New: role matrix (5 roles × 22 protected routes, plus 401 unauthenticated on each), pay-rate probe, TOTP gate for unenrolled and unverified firm sessions, replay, recovery code single use, lockout on the sixth attempt with identical bodies, `X-Tenant-Id` ignored, own-membership read via ORM and raw SQL (zero rows without `app.user_id`; insert rejected, update/delete match nothing with it), tenant switch without membership 403 and unchanged, extra-policy allow-list, `audit_log` isolation, append-only for `app_rw` and `app_owner` including drop/disable attempts, audit rows and atomicity of role change + audit row, firm audit readable by firm roles only, cookie flags and hash-only storage, rotation, idle and absolute expiry, logout, CSRF, key rotation, crypto ring, and a suite-wide log capture (SQLAlchemy statement logging on) that finds no password, secret, code, recovery code, or session id. **Mutation checks done by hand**: a `sneaky` policy on `_rls_probe` and a second policy on `membership` each make the enumeration test fail; a registered append-only table without triggers fails (in-process test). End-to-end against the local stack through the Vite proxy: login → enrol (QR/secret) → confirm → tenant list → admin joins a tenant without prior membership → switch → audit reads → logout → replayed code refused; cookie flags as specified. The React screens were not driven in a browser in this session (no browser automation available); `npm run build` passes.
**Decisions referenced / made**: D-10, D-11, D-12, D-13, D-14 (appended to `docs/DECISIONS.md`). Proposal for D-15 (`firm_membership`) recorded in `current-feature_02.md`.

## 2026-09-17 · F01 · Project skeleton & tenant isolation
**What**: Repo layout per BLUEPRINT §12 (`backend/`, `frontend/`, `docs/`, `db/`, `tests/fixtures`, `tests/golden`); `docs/BLUEPRINT.md` moved from the repo root. Docker compose Postgres 16 on port 5433 with a bootstrap script that creates `app_owner` (schema owner, migrations) and `app_rw` (application; not owner, `NOSUPERUSER`, `NOBYPASSRLS`) and grants `app_rw` DML through default privileges so migrations never name the role. FastAPI app with `/api/health`, config from environment, and a request-scoped session dependency that opens a transaction and sets `app.tenant_id` with `set_config(..., true)` (`SET LOCAL`). `tenant_session(engine, tenant_id)` context manager for workers and scripts. Alembic baseline with `firm`, `tenant`, `user`, `membership`, and the test-only `_rls_probe`. Migration helper `enable_tenant_rls(table)` that enables **and forces** RLS and creates the `tenant_isolation` policy. React + Vite shell that calls the health endpoint. GitHub Actions CI: ruff, migration up/down/up, pytest, frontend build. README and OPERATIONS runbooks.
**Why**: BLUEPRINT §3.8 and §11: isolation is enforced by the database, not by remembering a `WHERE` clause. Doing it in the first migration means every later table inherits the guarantee and the CI test (`tests/test_rls.py`) enumerates every `tenant_id` table so a missed helper call fails the build. Policy uses `NULLIF(current_setting('app.tenant_id', true), '')::uuid` so a missing or expired setting yields zero rows and rejected writes rather than a cast error.
**Migrations**: `0001_baseline` (reversible; downgrade drops the five tables and the `membership_role` enum). Verified up → down → up on an empty database in a test and via the CLI.
**Tests**: 25 passing. RLS enabled+forced+policy+leading index on every `tenant_id` table; cross-tenant reads return nothing via ORM and raw SQL as `app_rw`; cross-tenant inserts and updates are rejected; no context → zero rows, insert fails, also for the owner (FORCE); `app_rw` cannot disable/unforce RLS or drop the policy; context does not leak across pooled transactions; request dependency scopes correctly per header; product name appears in exactly one constant per side. Mutation check done by hand: an unprotected `tenant_id` table makes the enumeration test fail.
**Decisions referenced / made**: none. D-09 (name) still open; working name lives in `backend/app/core/product.py` and `frontend/src/product.js` only.
**Dependencies added**: fastapi, uvicorn, sqlalchemy, alembic, psycopg[binary], pydantic-settings; dev: pytest, httpx, ruff. Frontend: react, react-dom, vite, @vitejs/plugin-react.
**Follow-ups**: F02 replaces the `X-Tenant-Id` header placeholder in `require_tenant_id` with the authenticated tenant. See "Discovered" in `current-feature.md` for the rest.
